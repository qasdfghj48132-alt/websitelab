# Регистрация и авторизация — «Уютный берег»

## Важно
Текущая публикация на GitHub Pages обслуживает только статические HTML/CSS/JS-файлы и **не запускает PHP**. Регистрация, вход, профиль, восстановление пароля и закрытая страница заработают только на сервере с PHP 8.1+ и MySQL 8+ (например, XAMPP или PHP-хостинг).

## Локальный запуск через XAMPP
1. Установите XAMPP с Apache, PHP и MySQL.
2. Скопируйте проект в `C:\\xampp\\htdocs\\uyutny-bereg`.
3. Запустите Apache и MySQL в панели XAMPP.
4. Откройте phpMyAdmin: `http://localhost/phpmyadmin`.
5. Импортируйте файл `database.sql`.
6. Скопируйте `config.example.php` в `config.php`. Для стандартного XAMPP обычно подходят host `127.0.0.1`, database `uyutny_bereg`, user `root`, пустой пароль. Если у вас другие настройки, измените их в `config.php`.
7. Откройте `http://localhost/uyutny-bereg/`.

## Проверка
- Нажмите «Войти / Регистрация» в шапке.
- Создайте аккаунт: логин (латиница/цифры/_), пароль от 10 символов, ФИО, почта, аватар JPG/PNG/WebP до 2 МБ.
- Войдите и откройте «Личный кабинет».
- Измените ФИО, почту, аватар или пароль. Логин намеренно не редактируется.
- Нажмите «Выйти», затем проверьте, что `profile.php` перенаправляет на главную без авторизации.
- Для проверки «запомнить вход» закройте браузер, не нажимая «Выйти», и откройте сайт снова.
- В окне входа нажмите «Забыли пароль?». Для существующей почты ссылка восстановления выводится прямо в окне; она действует один час. В учебной версии письмо не отправляется.

## Файлы
- `database.sql` — таблицы пользователей, токенов длительного входа и восстановления пароля.
- `config.example.php` — пример настроек. Реальный `config.php` не добавляется в Git.
- `auth.php` — API регистрации, входа, выхода, профиля и сброса пароля.
- `profile.php` — закрытый личный кабинет с серверной проверкой доступа.
- `reset.php` — страница установки нового пароля по одноразовой ссылке.
- `auth.css`, `js/auth.js` — всплывающее окно и интерфейс.

## Защита
- PDO и подготовленные выражения для запросов к MySQL.
- `password_hash()` / `password_verify()` вместо MD5.
- CSRF-токен для POST-операций.
- `htmlspecialchars()` при выводе пользовательских строк в HTML.
- Аватар проверяется по MIME-типу и размеру; имя файла генерируется случайно.
- Сессия обновляет идентификатор после входа; cookie длительного входа HttpOnly, SameSite=Lax, содержит случайный секрет, в БД хранится только его SHA-256.
- Сброс пароля — одноразовый токен с ограничением срока действия.

Перед размещением в интернете обязательно используйте HTTPS, отдельного пользователя MySQL с ограниченными правами и непубличный `config.php`. Это учебная реализация; для публичного сервиса дополнительно нужны rate limiting, журналирование и настройка почтовой отправки.
